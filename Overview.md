# Local RAG Using Ollama — Project Overview

A fully local, privacy-preserving Retrieval-Augmented Generation (RAG) system that lets you ask natural language questions over your own PDF and DOCX documents. All processing runs on-device using a local LLM served by Ollama — no cloud APIs, no data leaving your machine.

---


## What It Does

You point the system at your documents, it ingests and indexes them, and then you can chat with them via a command-line interface. Answers are grounded in the actual content of your files, generated by Llama 3 running locally through Ollama.

---

## Key Features

- **Document ingestion** — loads PDF and DOCX files, splits them into overlapping chunks, and stores everything locally
- **Vector embeddings** — each chunk is converted to a vector using Ollama's embedding endpoint
- **PostgreSQL + pgvector** — embeddings and chunk text are stored in a local Postgres database with vector similarity search
- **Chat history** — every question and answer is persisted to the database across sessions
- **Local LLM generation** — answers are generated by Llama 3 via Ollama, fully offline
- **CLI interface** — interactive chatbot loop with document selection; no GUI

### Phase 1 — Ingestion

1. `ingestion.py` reads all PDF and DOCX files from `data/` and extracts raw text
2. `chunking.py` splits the text into overlapping segments for better retrieval coverage
3. `model.py` calls Ollama's embedding endpoint to generate a vector for each chunk
4. `database.py` stores the chunk text, its vector, and source metadata into PostgreSQL via pgvector

### Phase 2 — Query & Generation

1. User selects a previously ingested document from the CLI
2. User types a question; `model.py` generates an embedding for the query
3. `ingestion_query.py` runs a cosine similarity search against pgvector to find the top-K most relevant chunks
4. `engine.py` assembles a prompt — retrieved chunks as context plus the user's question
5. `model.py` sends the prompt to Ollama (Llama 3) and returns the generated answer
6. The question and answer are saved to the chat history table in PostgreSQL

## Usage

```bash
# Ingest documents (run once per new batch of files)
python main.py

# Start the chatbot
python llm_query.py
```

When running the chatbot, select the document you want to query, then ask questions in a loop. Type `quit` or `exit` to stop.

---

## Limitations

- Only PDF and DOCX formats are supported
- Command-line only — no web or desktop GUI
- Requires a local PostgreSQL instance (heavier setup than file-based vector stores)
- GPU recommended for acceptable Llama 3 performance
- Documents must be re-ingested if their content changes
- Designed for single-user local use only
